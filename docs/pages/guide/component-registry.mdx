# 组件血缘清单

> 「这个组件是哪来的、坏了该怎么修」——维护者视角的总账。消费方找组件请按
> Storybook / 文档站的**功能域**导航；本页回答的是另一个维度：**血缘**。
>
> 与 [shadcn/ui 对照表](/guide/shadcn-mapping) 的分工：对照表管「shadcn 的 X
> 在我们这叫什么」（找替代品），本页管「我们的 X 是哪来的」（定改法）。

## 血缘四档与改法纪律

| 血缘档 | 含义 | 改法纪律 |
|---|---|---|
| **shadcn 原版** | 与上游逐字一致（或仅 import 路径差异） | 去 ui.shadcn.com 对 diff 同步，**禁止加私货**；要加能力先考虑独立文件 |
| **shadcn 适配** | 原版 + 文件头注释列明的改写 | 对上游同步 + 维护适配层注释；适配原因消失时（如升 TW v4）还原原版 |
| **自研** | shadcn 没有的组件 | 全责自管，需求与 bug 都进本仓 |
| **组合封装** | 拼现有组件的业务壳 | 改壳不改底座；底座问题去对应基础件修 |

> 抄新组件的纪律见对照表头部：**只抄 Radix 变体**（URL 无 `/base/`、`/aria/` 前缀）。
>
> **自研 vs 组合封装的硬判据**：看文件 import——拼装了**包内其它组件**当底座（如
> ConfirmDialog → AlertDialog）= 组合封装，底座问题去底座修；只用原生元素 / Radix
> 原语 / 三方库（如 PageHeader 纯 markup、DateRangePicker → react-day-picker）= 自研，
> 全责自管。「底座」列即答案：列里是包内组件名的就是组合封装。
